Field Service mobile boundary

Mobile is a workflow decision, not just a smaller screen

Microsoft's mobile platform supports technician work and customization, but the online/offline requirement changes the implementation and acceptance plan.

What Microsoft supports

The Field Service mobile app is a Power Platform model-driven app for work orders, customer assets, accounts, contacts, and technician tasks. Connected Field Service can show recent IoT activity related to an asset in the mobile app.

The documented Connected Field Service IoT mobile experience requires an active internet connection.

  • Online pathEvaluate Asset 360 in the technician journey with customer identity, work-order mapping, and device testing.
  • Offline pathDefine an offline profile, allowed tables, filters, sync behavior, data volume, and conflict handling before implementation.
  • Experience choiceThe refreshed Field Service mobile experience currently does not support offline mode.
  • Component choiceHTML web resources have partial, platform-dependent offline support. The current card is not certified offline-ready.

Recommended next sequence

Validate first, then choose the mobile shape

This is a proof sequence, not a final production architecture recommendation.

  1. Validate customer data and identityUse the already verified Customer Service and conversational patterns to confirm fields, relationships, roles, freshness, and policy.
  2. Run a Field Service mobile design spikeOnce the technician journey and connectivity needs are known, test the smallest supported online or offline implementation.
  3. Justify any separate appChoose a customer-owned web or mobile product only when a distinct audience, brand, or channel requirement warrants the added ownership.

Technical review

Six decisions unblock a bounded proof

A 30-minute data and architecture review can separate source readiness from assumptions and select the right proof route.

  • Which users need case, conversational, technician, or separate customer access?
  • Which source APIs and fields exist, and who owns them?
  • How do customer, case, contact, serial, asset, IoT device, and work order relate?
  • Is mobile online-only, intermittently connected, or required to work fully offline?
  • Which tenant, environment, app, form, roles, and device policies apply?
  • Which measures define proof success before any production or portal-replacement decision?
