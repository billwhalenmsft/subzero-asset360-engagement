Component responsibilities

Small ownership boundaries with explicit failure behavior

No layer broadens authorization granted by the layer before it.

Dynamics 365 adapter

Reads case context, opens one Asset 360 side pane, preserves existing handlers, and performs no case write.

  • Approved case mapping only
  • Wrong organization or mapping fails closed
  • Service Toolkit remains independent

Microsoft 365 and Cowork adapter

Packages connector metadata, tool descriptions, skill guidance, and an OAuth registration reference.

  • No secret in package files
  • Delegated appliance-read scope
  • Native MCP Apps rendering

Protected MCP service

Validates the token and maps an authorized user to an evidence role and appliance scope.

  • Strict input schemas and limits
  • Generic inaccessible-resource responses
  • Health separated from protected operations

Asset 360 evidence engine

Resolves context, separates profile and connected modes, and preserves source boundaries.

  • Observations before interpretation
  • Missing and stale evidence retained
  • No arbitrary model diagnosis

MCP Apps widget

Returns a digest-bound, self-contained visual resource with Overview, History, and Assessment.

  • No widget network dependency
  • Views match requested evidence
  • Text fallback without weaker authorization

Customer data adapters

Future read-only connections to approved profile, event, telemetry, case, and knowledge sources.

  • Explicit field dictionary and units
  • Customer source identity
  • Retention and audit policy to agree

Request flows

Case initiated or conversation initiated

Both paths converge on the same authorization and evidence contract.

Case-initiated flow

  1. Open an authorized service case.
  2. Read only the case identifier and approved mapping context.
  3. Open Asset 360 in one side pane.
  4. Obtain a delegated token for the protected service.
  5. Validate identity, resolve the appliance, and return requested evidence.
  6. Render the card beside the case.

Conversation-initiated flow

  1. Ask Cowork or Copilot for a case or appliance view.
  2. Resolve ambiguity with bounded search or case context.
  3. Supply a delegated token through the token store.
  4. Validate and invoke only the selected read-only tool.
  5. Mount the returned Asset 360 widget.
  6. Request history or assessment only through explicit follow-up.

Trust boundaries

Controls follow the request end to end

Delegated identity is necessary but not sufficient; each service boundary performs its own bounded validation.

Failure behavior

Fail closed without hiding uncertainty

The experience should distinguish unauthorized, unavailable, ambiguous, stale, and unknown states rather than collapsing them into one answer.

  • No or invalid tokenReturn unauthorized; do not enumerate tools or evidence.
  • Wrong client, audience, tenant, or scopeReject before tool execution.
  • Unassigned user or applianceFail closed without disclosing inaccessible appliance identity.
  • Ambiguous case or applianceReturn an explicit unresolved state; do not guess.
  • Profile-only accessOmit measurements, alerts, settings, status, and firmware.
  • Stale or missing readingsPreserve source age and missing values; do not infer health.
  • Unsupported field or rangeReject with a bounded validation response.
  • Widget or source unavailableUse a safe fallback while preserving authorization and source time.

Proposed delivery

Move from proof pattern to customer-owned decision

Each phase ends with evidence and an explicit decision before the next boundary is crossed.

Discover and classify

Confirm journeys, models, users, owners, sources, sensitivity, and regional constraints.

Contract the evidence

Define fields, units, timestamps, freshness, missing-data behavior, relationships, and non-goals.

Build foundations

Create customer identity, Azure, Dynamics 365, Microsoft 365, monitoring, and rollback resources.

Connect a bounded sample

Implement read-only adapters and validate identity, mappings, tools, cards, and fail-closed behavior.

Run and measure

Compare current service work with evidence-assisted human review using agreed measures.

Decide on production

Review security, reliability, support, cost, value evidence, and unresolved risks before expansion.

Open architecture decisions

Intentionally unresolved before customer discovery

The proof should inform these decisions; the demo should not pretend to have made them.

Sources and mediation

Exact systems, event model, field ownership, and whether an integration layer is needed.

Network and region

Private ingress, egress, firewall, DNS, residency, and regional topology.

Data lifecycle

Persistence, caching, retention, replay, audit, deletion, and approved support access.

Reliability and support

Availability target, scale, recovery objectives, monitoring, incident response, and ownership.

Credential strategy

Certificate or secret, rotation, token-store configuration, and customer operational controls.

Production packaging

Promotion, certification, release, rollback, and broader Microsoft 365 availability.
